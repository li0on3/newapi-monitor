# New API 功能页架构

[简体中文](CUSTOMER_CONSOLE.md) | [English](CUSTOMER_CONSOLE_EN.md)

普通用户在监控平台内使用监控总览、概览、数据看板、API 密钥和使用日志五个独立顶级模块。其中四个账户业务页是外置 New API 功能页；所有页面都不修改 New API 源码，不复制用户、Token、额度或日志表，也不接管 New API 的鉴权和计费。

## 请求链路

```text
浏览器 -> 监控平台固定 BFF -> New API 固定 API
          session + 已校验 user_id
```

1. 浏览器携带 New API 的 `session` Cookie 和 `New-Api-User`。
2. 监控平台通过 New API `/api/user/self` 校验 Session、账号状态和用户 ID 一致性。
3. BFF 只向代码内固定的 New API API 转发当前 Session 与已校验用户 ID。
4. New API 继续负责数据范围、Token 所有权、额度校验和所有写入。

监控平台不批量复制 New API 用户表。用户每次登录时按 Session 实时同步当前身份；账号禁用、删除或角色变化会在短缓存失效后自动生效，无需在两个平台重复维护账号。

为复用浏览器中的 New API Session 与 `uid`，生产环境应把监控平台挂载在 New API 的同一 Origin 下，例如 `https://api.example.com/monitor/`。独立域名或不同端口默认无法共享这两项浏览器状态，不应通过复制 Cookie 或管理 Token 冒充用户来绕过。

New API Admin 与 Root 默认映射为监控管理员，可使用全部监控模块；普通 New API 用户默认可使用按“用户端总览”范围过滤的监控总览，以及下列四个个人业务页面。普通用户界面使用中性“API 服务中心”身份，不展示 New API 品牌或技术运维模块。监控平台的紧急管理员没有 New API 身份，因此不能进入四个账户业务页面。显式角色覆盖只能改变监控入口，不能把普通 New API 用户升级为 New API 全局数据权限。

用户点击监控平台退出后，服务端设置独立的监控 SSO 抑制 Cookie。该 Cookie 不包含身份或凭据，只阻止监控自动复用 New API Session；用户主动点击“账号登录”后才解除。整个过程不会删除或修改 New API `session` Cookie。

监控登录页不采集或转存普通用户的上游账号密码。如果当前浏览器没有可复用的账号 Session，页面会停留在中性“API 服务中心”并提示用户先在账号服务完成登录，不会自动跳转到带上游品牌的页面。

## 页面和上游接口

| 页面 | 路径 | 数据源 |
| --- | --- | --- |
| 监控总览 | `/monitor/` | 监控 SQLite 中的渠道探测、真实日志聚合和资源指标；按用户端渠道范围过滤 |
| 概览 | `/monitor/console` | `/api/status`、`/api/user/self`、`/api/user/models`、`/api/token/`、日志统计 |
| 数据看板 | `/monitor/console/analytics` | `/api/data[/self]`、`/api/data/flow[/self]`、日志统计 |
| API 密钥 | `/monitor/console/keys` | `/api/token/*`、`/api/user/models`、`/api/user/self/groups`、`/api/data/flow/self` |
| 使用日志 | `/monitor/console/logs` | `/api/log/` 或 `/api/log/self`、对应统计接口 |

源角色为 New API 管理员时，数据看板默认使用全局接口，也可显式切换到当前账号的 `self` 接口；普通用户由服务端强制只调用 `self` 接口。按用户名筛选仅在管理员全局范围生效。

普通用户不会看到技术“监控”工作区，只能读取用户端开启的渠道卡片和对应状态汇总。官方状态独立页、监控日志、机器资源、事件、Key 查询、渠道配置和系统配置接口仍在服务端拒绝 Viewer；直接输入对应 URL 也不能绕过权限边界。

普通用户的渠道响应采用固定字段白名单，只包含展示所需的状态、延迟、可用率、模型范围和聚合指标；原始渠道名、探测配置、最近请求日志与上游错误正文不会下发。管理员和运维员仍可在技术视图中查看完整排障信息。

数据看板直接使用 New API 的真实数据，按模型和时间桶绘制堆叠趋势，并可在请求数、Token 和额度之间切换。请求数与额度总量始终以实时消费日志为权威源；模型、Token 与额度流向来自 New API `quota_data` 小时归集。两种口径不一致时，页面单独显示带符号的“总量与归集明细差额”，并明确提示差额可能来自归集时差、时间桶边界、保留策略或旧记录缺少分组等归因维度，不会把所有正向差额承诺为稍后必然消失的“待归集”。额度流向按页面可见的账号/密钥、分组和模型合并，隐藏的节点和渠道维度不会造成重复行；第 12 条之后聚合为“其他”，并通过差额行与权威总量闭合。较慢的旧请求结果不会覆盖用户后续选择。

## 数据与密钥

- 客户业务数据只在请求期间读取，不写入监控 SQLite。
- Token 列表只返回 New API 已脱敏的 Key。
- 明文 Key 只能由用户主动执行一次性查看，使用 POST、单独限速和 `Cache-Control: no-store`。
- 明文 Key 不进入配置、审计、应用日志、URL、localStorage 或 sessionStorage；关闭弹窗后从 React 状态清除。
- 所有 Token 写操作由 New API 再次校验所有权和业务规则，监控平台只记录脱敏操作审计。
- 监控平台只额外保存自定义密钥分组名称、颜色和 `user_id + token_id + group_id` 成员关系，不复制额度、日志或明文 Key；一个密钥可同时属于多个自定义统计分组。
- 自定义密钥分组与 New API Token 的原生 `group` 字段相互独立；后者仍用于 New API 路由/计费，前者只用于监控页面组织和统计。
- 个人密钥和分组用量固定读取 `/api/data/flow/self`，按不可变 `token_id` 关联当前账号的现有密钥。即使账号是 New API 管理员，该页面也不读取全局 Flow。
- 分组汇总采用“当前多重成员关系”口径。New API Flow 没有历史自定义分组快照，因此成员变更后，所选 1/7/30 天用量会按当前关系重新汇总；同一密钥会计入它所属的每个分组，账户总计按密钥去重，分组之间不可直接相加。
- 创建、修改、删除、批量分配和成员编辑均写入监控配置审计；写入前再次读取当前用户完整 Token 清单，拒绝不存在或不属于当前用户的 Token ID。删除分组不会删除密钥，也不会影响该密钥的其他分组关系。

## 兼容与故障边界

- BFF 没有任意 URL、路径、请求头或方法透传能力，避免升级兼容功能退化为 SSRF 或开放代理。
- 上游超时、非 JSON、超大响应和异常 HTTP 状态被转换为有限错误，不回显 Cookie、Token 或上游响应正文。
- 携带 Session、管理员凭据或 Key 的上游请求不会跟随 HTTP 重定向，避免凭据被转发到其他主机。
- New API API 合约发生变化时，只需调整 `dashboard_newapi_console.py` 及对应契约测试；New API 主业务不受监控平台故障影响。
- New API 功能页可以在“系统配置 → New API 功能页”整体关闭，或按页面逐项关闭。
- 旧版单分组成员表会在启动时自动迁移为多分组复合主键；旧前端发送的 `group_id` 字段继续兼容，便于滚动升级和浏览器缓存过渡。
- 数据库迁移在显式事务内执行；任一步骤失败都会保留旧表和原成员关系，修复异常数据后重启即可重试。
