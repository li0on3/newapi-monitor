# 数据口径与准确性

本文定义监控平台每个页面的数据源、统计口径、新鲜度和历史边界。页面展示与接口返回都应遵守这些约定；如果两个数字采用不同口径，界面必须明确说明，而不是让用户自行猜测。

## 核心原则

1. **权威源优先**：渠道配置、账号、密钥、消费日志和计费额度以 New API 只读接口为准；主机资源以本机采样为准；OpenAI 官方状态以官方 Status API 为准。
2. **总量与归因分离**：数据看板的请求数和额度总量来自实时消费日志；模型、Token、密钥和分组归因来自 New API 小时聚合。两者暂时不一致时，页面单独展示归集差额。
3. **当前值与趋势分离**：资源当前值、最高值和最低值来自原始样本；长区间曲线使用时间桶平均值，不能把桶平均误称为瞬时峰值。
4. **未知不等于故障**：没有探测样本或样本过期时显示“未探测/数据陈旧”，不会伪装成正常或异常。
5. **累计不等于无限保留**：“累计/历史总量”表示当前权威源仍可查询到的全部历史，受 New API 日志清理和监控平台保留策略约束。
6. **异常数据失败关闭**：权威接口缺少必需字段、返回错误类型、非有限数值或不一致分页时，整次查询返回错误；不把无法确认的数据替换为零值继续展示。

## 页面数据矩阵

| 页面/指标 | 权威数据源 | 口径 | 新鲜度与边界 |
| --- | --- | --- | --- |
| 渠道清单 | New API `/api/channel/` | 只同步 New API 当前渠道；只探测启用渠道；管理员与普通用户可分别配置可见性 | 默认每 5 秒同步；失效后全部标记未知，不把旧快照当实时数据 |
| 渠道健康 | 真实模型探测或 New API 内置测试 | 每个渠道只使用最新探测来源计算历史与可用率，避免混合两种探测协议 | 探测失效阈值为探测周期的 3 倍；阈值来自动态配置；累计可用率仅覆盖当前保留的探测样本 |
| 监控使用日志 | New API 消费日志（`type=2`） | 真实用户消费请求；排除配置中的监控探测 Token 和模型测试 Token | 默认 30 秒增量同步并带重叠窗口；默认保留 90 天；页面显示接入时间和最新样本时间 |
| 总览请求耗时 | 监控使用日志 | 24 小时请求数、平均耗时、P95、平均首字和慢请求；慢请求阈值来自系统配置 | 与日志采集器新鲜度一致；单次慢请求只影响展示，不直接触发外部告警 |
| 主机资源 | `psutil` 与只读 Docker Socket Proxy | 当前值和区间极值来自原始样本；趋势为分桶平均；样本覆盖率 = 已采样数量 / 所选范围预期采样数量 | 默认每 15 秒采样、保留 90 天；采样周期和 CPU/内存/磁盘阈值来自动态配置 |
| 事件 | 监控状态机与采集器 | 记录触发原因、恢复原因、状态、确认信息和关联元数据 | 已恢复事件默认保留 365 天；筛选时间按事件开始时间 |
| 告警投递 | SQLite 持久化 Outbox | 待发送、发送中、已送达、死信和取消状态均来自实际投递记录；状态数量跟随当前时间、渠道和搜索筛选，但不受当前状态页签限制 | 已投递和死信默认保留 30 天；支持完整分页；重试不会伪造新的业务事件 |
| OpenAI 官方状态 | `https://status.openai.com/api/v2/summary.json` | 仅作上游背景；只有配置为业务相关的组件才可参与整体状态 | 默认 60 秒采集；官方异常不会覆盖本地渠道探测结论 |
| New API 账号概览 | `/api/status`、`/api/user/self`、`/api/token/`、`/api/log/self/stat` | 始终为当前登录账号；账号累计请求、剩余额度、累计使用和 24 小时消费额度不混入全局数据 | RPM/TPM 是当前 60 秒速率，不是所选历史区间总量 |
| 数据看板总量 | `/api/log/` 或 `/api/log/self`、对应 `stat` | 请求数与消费额度为所选区间实时日志精确总量 | 与 New API 当前可查询日志一致 |
| 数据看板模型/Token/流向 | `/api/data/`、`/api/data/flow` 及 `/self` 版本 | New API 小时聚合归因；归集时差、时间桶边界、保留范围或旧记录缺少分组等归因维度造成的差额单独显示 | 普通用户超过 30 天的查询会按上游限制自动分段，任一分段失败则整次查询失败，避免返回不完整结果 |
| API 密钥 | New API Token API | 当前账号的真实密钥、状态、额度、模型限制和允许 IP；不限额密钥可能存在负剩余额度，按 New API 原值保留并以“不限额”解释 | 按请求实时读取；明文只在用户主动查看时返回一次，不持久化 |
| 密钥分组用量 | 当前密钥 + New API 小时流向聚合 | 只统计当前仍存在的密钥；已删除密钥历史用量单独说明；同一密钥属于多个监控分组时会分别计入各组 | 最新请求可能等待小时归集；分组总计不可相加 |
| Key 查询 | `/api/usage/token/`、`/api/log/token` 与 `/api/status` | 额度为 Token 权威累计值；调用统计仅汇总接口返回的最近 N 条记录，不冒充累计调用总量；展示换算单位实时读取 New API | N 与查询频率可动态配置；本地换算配置只作为漂移校验值，不能覆盖 New API 权威单位 |

## 时间范围

- “今天、近 7/30/90 天”和自定义日期使用包含首尾的时间范围。
- “累计/历史总量”不构造虚假的固定开始日期；监控本地数据从最早保留样本开始，New API 数据从其当前可查询历史开始。
- 后端统一使用 Unix 时间戳，浏览器按用户本地时区显示。
- 固定历史区间不自动刷新；包含当前时间的实时区间按页面配置刷新。

## 对账规则

### 数据看板

- `请求数 = New API 消费日志 total`
- `额度总量 = New API 消费日志 stat.quota`
- `模型归集差额 = 实时请求/额度总量 - 小时模型归集总量`
- `流向归集差额 = 实时请求/额度总量 - 小时流向归集总量`

差额为正只表示实时日志总量高于小时归集明细，可能来自归集延迟、时间桶边界、历史保留范围或旧记录缺少模型、密钥、分组等归因维度；差额为负表示小时归集明细高于当前可查询日志，也可能来自保留范围或时间桶边界差异。平台不会仅凭差额方向臆测唯一原因，也不会承诺正向差额一定会在后续归集消失。无论正负，页面总量保持使用实时消费日志，并明确列出差额。

### 监控日志

部署验收应在同一完整时间窗口内比较 New API `type=2` 日志与监控 SQLite：

- 排除配置中的探测 Token 后，请求 ID 集合必须一致；
- 行数、渠道、模型、耗时、首字和流式标记必须一致；
- 不允许重复请求 ID；
- 采集器失败时保留旧数据，但必须报告失效，不能静默宣称已同步。

### 资源

- 页面“当前值”必须等于所选区间最后一条原始样本；
- “平均/峰值/最低”必须对所选区间原始样本计算；
- 图表点可以分桶，但提示框必须标注为时间桶平均值；
- 样本覆盖率按原始样本数与配置采样周期推导的预期样本数计算；时间跨度覆盖另行返回，不能替代采样完整度；
- 阈值必须来自系统动态配置，不能在前端硬编码。
- “超过阈值”统一使用严格大于（`>`）；等于阈值时不会被页面、周期报告或告警状态机误标为已超限。

## 发布验收

每个版本至少执行：后端完整测试、前端完整测试与构建、Playwright E2E、Docker Compose 校验、镜像构建、生产健康检查、同窗日志对账、渠道清单对账、资源最新值对账、公开页面桌面与移动端检查。
