# CPA 周配额监控

CPA 周配额是与 New API 监控完全隔离的管理员功能，用于只读采集 CLIProxyAPI / API Management 中 Codex 与 Antigravity 账号的周限额、重置时间和附近请求压力。

## 数据流与边界

1. 监控后端使用 CPA 管理密钥读取当前启用的凭据清单。
2. 后端通过 CPA 的受控 `api-call` 能力请求供应商固定配额接口：Codex 使用 ChatGPT Usage，Antigravity 使用 Cloud Code 配额摘要。
3. 可选读取 Token Usage Tracker 的 1 小时、6 小时和 24 小时聚合，用于解释近期请求压力。
4. SQLite 只保存不可逆账号标识、脱敏账号、配额百分比、重置时间和聚合请求指标。

`management key`、`auth_index`、`project_id` 和上游 Token 不写入配额历史，也不返回浏览器。管理密钥按其他平台 Secret 的相同机制使用 `MONITOR_SECRET_KEY` 加密保存。

## 告警策略

- 默认每 30 分钟采集一次，最低允许 5 分钟；手动采集每分钟最多提交一次。
- 真实剩余配额 `<= 20%` 时告警；恢复到 `>= 25%` 后关闭事件，使用回差避免阈值附近反复开关。
- 持续偏低默认最多每 6 小时重复提醒一次。
- 预测不会单独触发告警。供应商配额公式不可见，平台只用真实配额下降速度作为基线，并用附近请求压力做有限修正。
- 单账号采集失败不会阻断其他账号；全部账号失败后采集器才进入失败状态。

所有阈值、采集周期、超时、重复提醒周期和请求压力开关均可在“系统配置 → CPA 周配额”动态调整。

## 预测口径

- 至少需要两个真实样本，且样本跨度达到 2 小时后才开始预测。
- 只比较同一个重置周期内的样本；周配额重置后重新建立基线。
- 消耗速度采用相邻下降样本的中位数，降低单点抖动影响。
- 1 小时相对 6 小时平均请求压力只进行有界修正，不会被当作供应商的实际扣费公式。
- 页面同时展示预计到达阈值、预计耗尽、是否会先重置以及低/中/高置信度。

## 权限与隔离

- 页面 `/monitor/cpa-quota`、设置页 `/monitor/system/cpa-quota` 和对应 API 仅管理员可访问。
- CPA 配额事件不进入 New API 总览状态，也不会出现在运维员可见的通用事件页。
- 功能只读，不会启停 CPA 凭据、修改配额、改变 New API 渠道或影响现有请求链路。

## 同机 Docker 部署

默认地址为：

```text
http://host.docker.internal:8317
```

仓库 `compose.yaml` 已为 Linux Docker 添加 `host-gateway` 映射。若 CPA 位于其他主机，在设置页填写其内网 HTTP(S) 地址即可。启用前应确认 CPA 管理接口只允许可信网络访问。

## 验收

启用后应确认：

1. 页面账号数与 CPA 当前启用的 Codex/Antigravity 凭据一致；账号只显示脱敏值。
2. 每个配额池的剩余百分比与 CPA 上游配额接口一致，日限额或 5 小时限额不会混入周限额。
3. 普通用户和运维员访问页面/API 均被拒绝。
4. New API 总览、渠道状态和事件统计不受 CPA 配额状态影响。
5. 数据库和 API 响应中不存在管理密钥、`auth_index`、`project_id` 或上游 Token。
